## What broke (typo in schema field name)
- test_hash_mismatch_rejected failed; assertion error suggested the
  validator wasn't running.
- Root cause: schema field was misspelled as `retriver_version` (missing
  an "e"), so test passing correctly-spelled `retriever_version` hit
  Pydantic's extra="forbid" check and bailed before any validator ran.
- mypy output was the diagnostic that solved it: "Unexpected keyword
  argument 'retriever_version' for 'Provenance'; did you mean
  'retriver_version'?".
- Lesson: when pytest fails confusingly, run mypy and ruff on the same
  code. Different tools surface different things; they often clarify
  each other.
- Lesson 2: when an error mentions a field by name, the field is the
  suspect. Read names carefully — silent typos in identifiers are
  notorious.
- Time to resolve: ~5 min once mypy was consulted.

## What broke (Pydantic + strict mypy on direct constructor calls)
- After fixing the schema typo, mypy still flagged 3 errors in the
  test that constructs Provenance directly (not via from_snippet).
- Errors: passing str where AnyUrl is expected; missing optional
  arguments embedding_model and nli_model.
- Root cause: Pydantic v2 + strict mypy require explicit values for
  optional Field-default-None arguments, AND require AnyUrl values
  to be wrapped explicitly (Pydantic coerces at runtime; mypy does
  not).
- Fix: pass embedding_model=None and nli_model=None explicitly;
  wrap the URL string with AnyUrl(...).
- Lesson: strict mypy + Pydantic Field defaults requires explicit
  passing. The runtime is more forgiving than the type checker; the
  type checker wins.
- Pattern: test_hash_mismatch_rejected was the only test using the
  direct constructor; from_snippet hides the verbosity. For tests of
  the integrity validator specifically, the verbosity is the price.
- Time to resolve: ~5 min.
