# Recovery container incident
- After stopping/restarting the codespace, the container failed to start with
  "unable to find user vscode: no matching entries in passwd file".
- Root cause: explicit remoteUser=vscode in devcontainer.json conflicted with
  Codespaces' provisioned codespace user owning /home/codespace.
- Fix: removed remoteUser line; let Codespaces assign its own user.

# LFS hook + push
- After committing the devcontainer fix, `git push` failed silently with
  "failed to push some refs", drowned in Git LFS warnings.
- Root cause: repo had LFS hooks installed (pre-push, post-commit) but the
  recovery Alpine container had no git-lfs binary. Hooks aborted the push.
- Fix: removed the LFS hooks from .git/hooks/ (we use DVC for data, not LFS).

# Recovery container kept relaunching
- After committing the devcontainer fix, every rebuild kept landing me in
  the Alpine recovery container with Python 3.12.13 and no uv.
- Root cause 1: the python:1-3.11-bookworm image had a user/UID conflict
  with Codespaces' provisioned user.
- Root cause 2: regular "Rebuild Container" kept reusing the broken
  cached layer.
- Fix: switched to mcr.microsoft.com/devcontainers/universal:2-linux
  (Codespaces-blessed image), then deleted the codespace via the GitHub
  web UI and created a new one to bypass the cache.
- Full Rebuild Container used instead of standard.


## What broke (CI lint job, post-day-1 push)
- Local environment: all green. CI: ruff failed with I001 on
  tests/unit/schemas/test_variant.py imports.
- Root cause: version drift. Local Codespace had an older ruff (likely
  0.5.x from when post-create.sh ran originally); CI installed ruff
  0.15.12. Newer ruff is stricter about import-block organization.
- Fix:
  1. uv run ruff check ... --fix to reorder imports.
  2. Pin ruff==0.15.12 (and other dev tools) exactly in pyproject.toml.
  3. ADR-0007 to record the decision and update procedure.
- Lesson: "all green locally" is not a guarantee. Until tool versions
  are pinned, CI can disagree with local at any moment. Pin early.
- Lesson 2: when CI fails for what looks like a mysterious reason, the
  first question is "what version of the tool is CI running, and is it
  the same as mine?". This is the canonical first move.
- Time to resolve: ~10 min once cause was identified.

## What broke (the import-order fight)
- ruff inside the pre-commit hook environment and ruff invoked via
  'uv run' had different versions and opposite opinions on the same
  imports. Each fix reverted the other.
- Pre-commit hook ruff: v0.5.0 (old, still applies ANN101).
- pyproject.toml ruff: 0.15.12 (current, removed ANN101, sorts imports
  differently).
- Fix: pinned pre-commit ruff and mypy hook versions to match
  pyproject.toml exactly. Cleaned and reinstalled hooks.
- Lesson: when you have two copies of the same tool in a project, they
  will eventually fight. Always align versions.
